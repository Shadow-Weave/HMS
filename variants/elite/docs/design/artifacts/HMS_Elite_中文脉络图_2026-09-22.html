5 · 整理：从中文句子里读出谁、做了什么、涉及谁 中文规则

谁：句首的人名后面跟着「说 / 问 / 告诉 / 要求 / 计划 / 喜欢 / 在 / 去…」这 36 个动词之一，就认为它是主语；「我…」记为用户本人。主语同时记为「说话人」。
做了什么：动词对到固定的动作类型——说→says、问→asks、计划 / 打算 / 要→plans、喜欢→likes、讨厌→dislikes、在→is_at、去 / 去了→went_to、买→buys……动词后面的短语记为宾语。
涉及谁：你给的人名名单（8 个）直接匹配；再加句首人名规则和「和 / 跟 / 给」后面的名字。原来会把「要求团队」「硬盘假装」当成人名的旧兜底规则，在中文模式下已关掉。
情绪和话题：中文词表——饭菜、购物、游戏、音乐、出行、家务、工作。时间：昨天 / 上周 / 3 天前 / 1 月 5 日，原来就支持。
效果
冒烟库 980 条记忆里 979 条主语是人名（杰克 228、露西亚 179、卡特里娜 175…）；动作类型 说 803 / 问 114 / 计划 7 / 买 3

7 · 落库，关键词索引按两字一组切 中文规则

中文没有空格，不切的话整句是一个词，查「小丸子」找不到「樱桃小丸子今天来了」。切成两字一组：「杰克要求团队」→ 杰克 · 克要 · 要求 · 求团 · 团队，查询也同样切，两字的词就能对上

中文规则到底起了什么作用

不加分。四选一的成绩由「意思相近」这一路加上一个好的中文嵌入模型决定。规则的作用是把每条记忆的「谁、做了什么、涉及谁」填对：不开规则时主语几乎全空，开了之后 979 / 980 条是人名。这决定了状态卡能不能按人整理、能不能按人过滤，以及以后做「他上次说什么」这类功能有没有依据。

两字一组的关键词索引目前是负贡献：它让记忆行的命中率掉了 4 个点。要用的话把关键词权重从 0.5 降到 0.25 以内再测，或者只在语义那一路找不够时才启用。

给中文产品的配置

embedder = fastembed / BAAI/bge-small-zh-v1.5，512 维
ingest.zh_rules = True（取主语、说话人、涉及的人）
ingest.entity_names = [你的用户和常提到的人]
retrieval.w_keyword 先降到 0.25 再测，或暂不开两字一组索引

保留意见：这次的中文数据是机器翻译的通顺书面语，比真实口语转写干净；数据集自带的中文语音转写原句可以做下一轮，不用翻译费。每种配置只跑了一次。
