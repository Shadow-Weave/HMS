01双平面

整个系统只有一个结构性主张：查询和继承是两件事，不该由同一个数据结构承担。

State Index — 状态索引

hms_elite/mvmi/ · 1,901 行

  • 热路径：add / search / get_all
  • 七个轴：时间、有效期、实体、主题、角色、情感、尺度
  • 只存坐标与出处，不存边
  • 有效期是 WHERE 子句的一部分，不是事后过滤

Support Graph — 支持图

hms_elite/graph/ · 1,660 行

  • 继承路径：why / compile(deep) / consolidate
  • 六类边：temporal、causal、revision、conflict、use、distill
  • 每条边至少一个见证锚点，零见证直接抛异常
  • 高层 InterfaceEP 是低层子图的接口，不是摘要

03存储与不变量

一个 SQLite 文件装下全部平面。83 条 DDL 语句由枚举生成：22 张表、39 个索引、22 个触发器。

四条不变量，三层强制

  • 见证必需anchor_ids 是 Annotated[list[str], Field(min_length=1)]；DDL 上是 NOT NULL REFERENCES anchors；insert_edge 在建模型之前就检查见证为空并抛 WitnessMissingError。
  • 原子不存边模型校验器拒绝 content 里出现 edges、src_id 等键；mvmi/ 无法导入 graph/；search() 不碰任何 graph_* 表。
  • 修订代替删除BEFORE DELETE 触发器拦截证据表与状态表的物理删除；BEFORE UPDATE 触发器让内容列不可变，只有有效期、置信度、可见性等少数列可改。
  • 高层是接口interface_eps.primary_support_node_id NOT NULL，支撑节点至少 2 个；只有边界边带 witness_edge_id，触发器据此自动写 edge_projections。

事务纪律

StateStore 是唯一跑 SQL 的地方，113 个公开方法。连接以 isolation_level=None 打开（自动提交），事务由显式 BEGIN IMMEDIATE 界定，配一个可重入锁与深度计数器。游标在锁内取完行才释放——这是一次审查确认的并发缺陷的修复点。时钟与 id 工厂都可注入，测试因此逐字节可复现。

代价要说清楚。系统从不物理删除任何状态行。可回滚、可审计、可解释都建立在这上面，但库的体积随写入单调增长，没有压缩路径。Mem0 的原地覆盖让可搜索集合始终正比于不同记忆的条数。

04写入路径

两条路：对话消息走 LLM 抽取，结构化事件走零 LLM 的闭包构建。

对话消息 · add()

  1. 落证据事务 A
    每条消息归一化成 SourceEvent，算 sha256 得 payload_hash，生成 Anchor。相同 (哈希, 时间, 范围) 的事件去重。这一步先提交，之后崩溃也能靠 consolidate(collect) 捡回。
  2. 抽取与决策无锁
    取最近 10 个事件与最相似的 10 个有效原子作上下文（真实 id 从不暴露给 LLM，用 '0'..'n' 代替）；抽出带 subject / predicate / objects / date 的结构化观察，而非一句话；带行动闭包的消息额外抽 EP 六元组；批量算向量；对每条新观察跑修订决策。
  3. 物化事务 B
    按决策落原子：ADD 新开谱系；REVISE 归档旧版、新版进同一谱系版本 +1、写 revision 边；CONFLICT 新谱系加 conflict 边；NONE 给旧原子加一个见证。同时写轴表、向量、图节点，以及 temporal 与 use 这类便宜的行内边。

结构化事件 · add_events()

tool_call 压栈，test_log 弹出最近未闭合的动作，拼成一个 (u, b, a, y, r, κ) EP，锚点同时挂动作与结果两个事件。结果为负的 EP 自动派生一条约束原子，用 distill 边连回去。全程零 LLM 调用，所以 add_events 一返回，工作状态卡的失败路径与下一步动作就已经可以生成。

05检索路径

先用 SQL 轴门控收窄候选集，再对候选集算五个信号。这与"取回 top-k 向量再重排"是两种不同的检索模型。

  1. 解析过滤
    Mem0 的完整语法解析成 AST：AND / OR / NOT、in / gte / contains、'*'、meta.<key>。顶层 AND 里的标量范围键会被上提。
  2. 规划查询
    识别中英文月份、ISO 与相对日期 → 硬性时间门；识别实体提示 → 硬性实体门；识别 retry.ts 这类标识符 → 关键词权重 ×2。
  3. 轴门控
    SQL 层施加范围、有效期、过滤 AST、尺度、时间门、实体门，上限 2000 条候选。门控为空时退回一次去掉计划门的查询，primary_axis 标为 fallback。
  4. 融合与阈值
    阈值作用在融合后的分数上，所以轴命中但向量弱的结果不会被误杀。
semantic = max(0, cos(q, v))
keyword = Σ w(t) over Q∩A / Σ w(t) over Q w=2.0 标识符，否则 1
entity = |Q∩A| / |Q| · 1/(1 + 0.001·max(0, deg−3)²)
recency = exp(−ln2 · age_days / 30)
support = tanh(n_undisputed_anchors / 3)

final = Σ(w·s) / Σ(w) 仅对激活信号 w = 1.0 / 0.5 / 0.5 / 0.25 / 0.25

explain=True 时每行带 14 个 score_details 字段：Mem0 的 7 个原样保留，再追加 recency_score、support_score、axis_gates、primary_axis、route 等。

06编译与溯因

检索返回行，编译返回状态。这是 Mem0 没有对应物的一层。

compile() → ContextIR

轴查询取候选（默认 50 条，阈值 0）→ 工作状态场景下补全该范围所有有效 EP 与约束 → 沿五类边扩展一跳 → 按有序规则把每个原子放进六个互斥槽之一 → 推导下一步动作 → 按份额切预算（约束槽保底 3 条，证据行永远保留）。产出的 ContextIR 有校验器保证各槽 id 互斥、每项都带见证。

  • slot_sharesfacts 0.30 · episodes 0.25 · constraints 0.15 · audit 0.15 · preferences 0.10 · skills 0.05，预算默认 1200 token
  • to_text()渲染成工作状态卡：当前目标 / 有效事实 / 失效假设 / 失败路径 / 约束 / 下一步 / 证据
  • to_pcir()降为 payload + witness + human_gloss + proof_obligations；见证缺失或存在未解冲突时抛 ProofObligationError

compile() 是只读的，前后表行数一致；fast 模式不触碰任何图表。

why() → 支持子图

目标可以是任意一种 id，也可以是一个问题（先编译一次取第一个约束/情节/事实作目标）。然后沿入边 {causal, use, distill, revision, conflict} 与出边 use 反向 BFS，遇到 InterfaceEP 按需展开，返回节点、带见证的边、锚点、路径，以及一条确定性的可读链条。

07修订与整理

每一次变更本身也是一个有证据的事件。

十一种反馈

处理器先写一个 feedback 类型的事件与锚点，再分发到十一个处理器。state_outdated 归档并可建后继；state_wrong 建 0.95 置信度的修订边并解决冲突；evidence_wrong 只把锚点标为有争议，绝不删除；只有 privacy_violation 能改可见性。

consolidate() 四阶段

  • orient只读，看最近活跃的主题、实体与未闭合的失败
  • collect补算缺失向量；把有锚点但没原子的事件重新走一遍抽取
  • consolidate建实体原子、时间边、因果边、冲突边；按连通分量 coarsen 成 L2 的 InterfaceEP 再 project；≥2 个支撑节点共享的不变量提升为 L3 技能；导出转移；编译并存档一张卡
  • prunestaleness = (1−recency)·(1−clamp(confidence−0.6))·(1−use_recency)；超阈值且低置信的归档，但钉住的、有冲突的、约束与技能永不动

同一范围连跑三次 consolidate()，graph_stats 完全相同——幂等已验证。

09hms4eye 对齐层

让本引擎可以直接替换掉 hms4eye 兼容服务里的 mem0。

那个服务的引擎接缝是 duck-typed 的七个方法，构造点唯一。HMSEngineAdapter 逐字对齐这七个签名，并遵守它的隐性约束：_hms_tenant_id 与 _hms_bank_id 必须原样存取（租户隔离靠 metadata 回读），且不能存在名为 update 或 delete 的方法（它有测试断言这两个属性不存在）。

读侧还把我们的富字段投影进 _hms_* 命名空间，所以那个服务一行代码不改就能看到真实的三态 fact_type 与时间区间。

点亮的是 entities、entity_graph、graph、consolidation 触发（native），以及 mental-models、directives、observations 清理、consolidation 恢复（adapted）。剩下 20 个 no-op 是 webhook、bank template、chunk 编辑这类服务层设施，本引擎也不做。

为什么叫 Elite。那个服务的分发名与导入名同为 hms-lite / hms_lite，与本项目原名完全相同，同一环境装不了。改名后已验证两个包可在同一进程共存，它的 MemoryService 能直接跑在本引擎上，跨租户越权读仍正确返回空。

11Mem0 更强的地方

这部分要诚实说。以下每条都核实过。

  • 异步AsyncMemory 镜像每个公开方法，阻塞调用包进线程池，实体加权带信号量。本包零 async def，异步应用要自己丢进执行器。
  • 规模化检索Qdrant HNSW 加稀疏 BM25，按查询长度校准的 sigmoid 归一。本包是在 SQL 候选集上暴力点积，候选上限 2000。
  • 重排Mem0 有真正生效的重排器接口与 Cohere/LLM 实现。本包接受 rerank=True 但只记一条警告，实际无操作。
  • 学习型实体识别spaCy NER 加向量归并；本包只有正则与词表，中文靠 CJK 规则，覆盖面窄。
  • 多模态视觉前置解析把图片部分换成 LLM 描述。本包不理解多部件消息。
  • 部署与运维自托管 REST 服务、托管平台客户端、批量接口、导出、遥测与首次运行提示。本包只有一个命令行。
  • 存储有界Mem0 的更新原地覆盖、删除真删，可搜索集合始终正比于记忆条数。本包从不物理删除，库随写入单调增长。
  • 生态成熟度按 issue 编号组织的回归测试、镜像提供者结构的测试树、三版本 CI 矩阵、版本号变更的 changelog 门禁。本包 222 个测试虽全离线且 4 秒跑完，但更年轻。
