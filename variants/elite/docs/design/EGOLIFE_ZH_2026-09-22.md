# 中文测试结果：换中文嵌入模型，准确率不掉（2026-09-22）

问题：嵌入模型是英文的，换成中文的准确率会不会下降很多？答案：不会。中文数据上，默认读法 68–70%，与英文的 70.1% 在噪声范围内。中文关键词与实体支持打开后也没有再涨。

## 一、怎么测的

- 数据：EgoLife A1 的 4,851 条转写用 deepseek-flash 译成中文（4,848 条译成，3 条保留英文；人名按固定表替换：Jake→杰克、Alice→爱丽丝、Tasha→塔莎、Katrina→卡特里娜、Lucia→露西亚、Shure→舒尔、Nicous→尼克斯、Choiszt→乔伊斯特；¥4.00，250 次调用，17 分钟）。204 道题用数据集自带的中文题面，选项人名同表替换，正确答案字母不变。
- 写入：lines 契约（默认），同一批次划分（290 批）与时间线，deepseek-flash。
- 读取：默认的 `context()` 混合上下文（会话卡 + 带时间戳记忆行，记忆在前）与只给记忆行两臂。
- 嵌入：BAAI/bge-small-zh-v1.5（512 维，fastembed 本地）。
- A：只换嵌入模型，库里的中文开关关着（关键词索引按 unicode61 整段成词，实体规则英文）。
- B：中文开关打开（`text.cjk_tokens = bigram` 关键词二元组索引、`ingest.zh_rules = True` 中文主语 / 说话人 / 实体 / 情绪 / 话题规则、评测台把 8 个人名作为实体名单传入）。
- 每轮：290 批写入 + 204 题 × 2 臂答题，约 22 分钟，$0.39（空闲档）。

## 二、结果

| | 英文基线 | 中文 A（只换嵌入） | 中文 B（加中文支持） |
|---|---|---|---|
| 默认读法 | 70.1%（143） | 68.1%（139） | 69.6%（142） |
| 只给记忆行 | 53.9%（110） | 55.4%（113） | 54.4%（111） |
| 记忆行 hit@20 | 84.3% | 84.8% | 80.4% |
| 混合上下文命中 gold | 87.3% | 90.2% | 85.3% |
| 存入记忆 | 12,963 | 10,384 | 10,641 |
| 有关键词命中的题（记忆行臂） | — | 11 | 204 |
| 有实体命中的题 | — | 14 | 107 |

## 三、结论

1. **换中文嵌入模型不掉分。** 语义一路撑起了 84.8% 的 hit@20；关键词与实体两路在 A 里几乎没有命中，准确率照样持平。之前「最坏掉 20 个点」的估计来自哈希嵌入下的消融，那时语义一路很弱，才显得另外两路重要；真实嵌入足够强时它们的贡献小得多。
2. **中文关键词二元组索引没有带来准确率，反而让记忆行的 hit@20 从 84.8% 降到 80.4%。** 关键词通道权重 0.5，二元组匹配很宽，把一部分语义命中挤出了前 20。产品上开二元组索引要同时把关键词权重调低，或只在语义召回不足时启用。
3. **中文规则的价值在结构，不在准确率。** B 存下的记忆主语和说话人是干净的中文名（杰克 228、露西亚 179……），A 里几乎全空。这影响状态卡「谁说了什么」和按人过滤，不影响四选一。
4. **推荐的中文配置**：嵌入 bge-small-zh-v1.5（或双语 bge-m3），`ingest.zh_rules = True`（取主语与实体），关键词索引保持二元组但把权重从 0.5 降到 0.25 以内再测，或先不开。

## 四、注意事项

- 中文转写是机器翻译的通顺书面语，比真实中文口语转写干净；数据集自带的中文 ASR 原句可以作为下一轮更接近真实的测试，不需要翻译费。
- 每种配置只跑了一次，±5 题是正常波动。
- 抽取提示词加了一句「陈述用原文语言写」，对英文无影响；lines 提示词没有哈希钉死。
- 中文实体规则仍有约 130 条碎片实体（「可以」「每个人」「并让大家」一类子句头），已去掉最大的一类兜底来源，剩余可用停用词表继续收窄。
