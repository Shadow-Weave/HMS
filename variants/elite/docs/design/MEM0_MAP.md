### 5.2 Versioning semantics
- Append-only delta log with a stable logical id: every mutation writes one immutable row; the *current* version lives only in the vector-store payload.
  - ADD: `_create_memory` (`main.py:1961-1991`) → `add_history(memory_id, None, data, 'ADD', created_at=, updated_at=, actor_id=, role=)`; batch path (`1064-1075`) writes `{memory_id, old_memory: None, new_memory, event:'ADD', created_at, is_deleted: 0}` (no updated_at/actor_id/role — two shapes for one event).
  - UPDATE: `_update_memory` (`2038-2098`) → `vector_store.update(vector_id, vector=new_emb, payload=new)` **in place** (old embedding/payload gone), then `add_history(memory_id, prev_value, data, 'UPDATE', created_at (preserved), updated_at (now), actor_id, role)` (`2080-2089`). memory_id stable across versions.
  - DELETE: `_delete_memory` (`2100-2128`) → `vector_store.delete`, then `add_history(memory_id, prev_value, None, 'DELETE', created_at=_normalize_iso_timestamp_to_utc(...), is_deleted=1)` (`2112-2122`). Old content survives ONLY as text in `history.old_memory`.
- Lineage is reconstructed purely by `ORDER BY created_at ASC, DATETIME(updated_at) ASC` on TEXT timestamps; only DELETE normalizes to UTC (`2109`), ADD/UPDATE store whatever caller/payload had (`1970-1971`, `2064`) → mixed naive/`+00:00`/`Z` strings can misorder. Verified on SQLite 3.53: with Redis/Valkey read-back shapes (`...SS.000000+00:00`) the history order becomes DELETE, UPDATE, ADD; with a caller `+05:30` `created_at` it becomes DELETE, ADD, UPDATE; the default Qdrant path is right only because all rows share a byte-identical string. `isoformat()` itself is variable-width (25 chars when `microsecond==0`, else 32) — §10.8.
- Vector-store mutation and history write are **not atomic** (store first, history second; no reconciliation).
- History table is write-only on the hot path; `search/get/get_all` never read it. `history()` = full table scan.
- Timestamp discipline: `created_at` honoured from caller metadata if present (`1033`, `1971`); `updated_at == created_at` on create; UTC ISO everywhere else.
- Soft expiry: `expiration_date` (`YYYY-MM-DD`, `_normalize_expiration_date` `427-439`) stored in payload; `_payload_is_expired` = `date.fromisoformat(exp) < date.today(UTC)` (`442-451`); filtered in Python **after** fetch with over-fetch `max(limit*4, 60)` (`1310`, `1355`, `1641`, `1670`) unless `show_expired`. This is Mem0's only validity concept — no `valid_from`, no `superseded_at`, day granularity. Enforcement is partial: only `search()` and `get_all()` filter; `get()`, `history()`, `delete_all()` and add()'s Phase-1 dedup/LLM context ignore expiry; strict `<` keeps a row visible through its expiry day; `update(expiration_date=None)` persists a literal `None`; `metadata['expiration_date']` bypasses normalization and, via `except ValueError: return False`, a malformed value never expires (and parsing leniency differs between Python 3.10 and 3.11+) — §10.8.
- Content hash = `md5(text).hexdigest()` (`1020`, `1969`, `2062`) — whitespace changes defeat dedup; dedup neighbourhood only top_k=10 by whole-conversation similarity (`926-931`).

## 9. Gotchas & pitfalls (merged from all readers)

### 9.1 Semantics / behaviour
1. **v2.0.19 `add()` is ADD-ONLY.** No LLM ADD/UPDATE/DELETE/NONE decision; `DEFAULT_UPDATE_MEMORY_PROMPT`/`get_update_memory_messages` exist (`prompts.py:176, 406`) but main.py never imports them. Conflict resolution = md5 exact-text dedup against 10 nearest neighbours + within-batch (`main.py:1005-1024`). Stores grow monotonically ("When in doubt, extract", L578); only explicit `update()/delete()` or `expiration_date` prune.
2. Dead code from the old flow: `uuid_mapping` (`935-937`, `2597-2599`) never read; `_should_use_agent_memory_extraction` (`739`, `2413`) never called; LLM `linked_memory_ids` never consumed; `utils.normalize_facts`, `ensure_json_instruction`, `format_entities`, `remove_spaces_from_entities`, `sanitize_relationship_for_cypher` unused by main.py.
3. Read/write scoping asymmetry: `add()`/`delete_all()` take ids top-level; `search()`/`get_all()` **reject** top-level ids (`ValueError`, `165-172`) and require `filters={...}` with ≥1 scope id.
4. `get()` returns `None` for a missing id; `delete()/update()` raise `ValueError`; `history()` on unknown id returns `[]`.
5. Sync `add()` raises `Mem0ValidationError(VALIDATION_002)` for bad `memory_type`; `AsyncMemory` raises plain `ValueError` (`2486-2489`). Sync `_add_to_vector_store(..., filters, ...)` vs async `(..., effective_filters, ...)` kwarg name differs (`879` vs `2533-2540`).
6. Procedural branch requires BOTH `agent_id is not None` AND `memory_type=='procedural_memory'` (`853`); `memory_type=procedural` with only `user_id` silently falls through to normal extraction. `SEMANTIC`/`EPISODIC` enum values raise.
7. The `prompt` arg of `add()` means two things: custom instructions appended to the additive user prompt (`946`) vs full replacement of the procedural SYSTEM prompt (`2005`).
8. `AGENT_CONTEXT_SUFFIX` applied only when `agent_id` set AND `user_id` absent (`941`), not "agent_id present and assistant messages exist" as the dead helper's docstring claims (`740-742`).
9. OSS cannot backdate: `add(timestamp=...)` raises (`817-818`); builder is called without `timestamp/current_date` (`948-953`) so Observation Date == Current Date == UTC today — the prompt's relative-time machinery is inert for historical imports. Legacy prompts f-string `datetime.now()` at import (`prompts.py:50, 111, 164`).
10. `summary` and `recently_extracted_memories` are never passed by main.py: `## Summary` always empty, `## Recently Extracted Memories` always `[]`.
11. Prompt/code contract mismatch: prompt says Existing Memories ids are UUIDs (L509) while main.py sends `'0'..'n'` (`938`) — harmless only because linking is ignored.
12. `parse_messages` includes `system:` lines (`utils.py:70-71`) → system prompt text leaks into `## New Messages`.
13. LLM JSON parse failures swallow to `[]` (`982-984`) while transport failures raise `LLMError` (`963-969`): callers can't distinguish "garbage output" from "nothing to extract" except via logs.
14. `remove_code_blocks` fence regex is anchored to the whole string (L134); `extract_json` returns only the first fenced block, and its brace fallback grabs first `{`..last `}` — a top-level JSON array cannot be salvaged. `json.loads(strict=False)` is required to tolerate raw control chars in quoted user text.
15. Metadata identity keys (`user_id/agent_id/run_id/actor_id`) in caller metadata are dropped with a warning on add (`363-365`) and ignored on update unless unchanged (`2060`). `created_at` IS honoured from caller metadata (`1033, 1971`) — callers can backdate; `updated_at` forced to `created_at` on create. Honouring is a presence check (`{'created_at': None}` stores `None`), un-validated, never UTC-normalized on create, and add-only (update re-pins the stored value, `2065`). Other caller keys collide silently: `role` survives on `infer=True` and is promoted as if real and copied to the history `role` column, `expiration_date` skips normalization, `memory_type` is spoofable, `data/hash/text_lemmatized/updated_at` are overwritten without warning, `id` is stored but never surfaced (§10.7).
16. Threshold gates the SEMANTIC score before fusion (`scoring.py:110-112`); default 0.1; BM25/entity boosts can never rescue a low-semantic candidate; candidates come only from semantic results (`1666-1677`); `max_possible` decided per query, so absolute scores are not comparable across queries.
17. No recency/decay term anywhere; `decay=True` raises. `expiration_date` is day-granular, UTC-date compared, post-filtered after fetch (expired rows eat the over-fetch budget) — and only in `search`/`get_all`: `get()` returns expired rows by id, `delete_all()` counts them, add()'s dedup and LLM context include them (§10.8).
18. `keyword_search` support detected by identity check at `__init__` (`543`); stores lacking the method silently run semantic-only. Qdrant passes the probe unconditionally but has a second, runtime gate — `fastembed` (in `mem0ai[extras]`, NOT `[nlp]`) plus a `bm25` sparse slot on the collection — whose failure is equally silent (§10.3). spaCy is an optional extra (`mem0ai[nlp]`, English `en_core_web_sm` only): without it `extract_entities → []` and `lemmatize_for_bm25 → raw text`, so BM25 and entity boosts silently vanish. Even when live, the `raw_score > 0` gate plus Qdrant-calibrated sigmoid make BM25 nearly inert on pgvector/Milvus/Redis/Weaviate (§10.2).
19. Dedup neighbourhood = top_k=10 by whole-conversation similarity (`926-931`); hash = md5 of raw text (whitespace defeats it); `existing_hashes` covers only Phase-1 results.
20. `delete_all` indexes `vector_store.list(...)[0]` (`1923-1925`) assuming `[[rows]]`, while `_get_all_from_vector_store` unwraps both shapes (`1329-1340`) — inconsistent `list()` contract handling; `list()` returns `[[rows]]` (FAISS/Chroma/Milvus), `(points, offset)` (Qdrant), `rows` (pgvector).
21. Filter-operator support is store-dependent: `'*'` is a no-op on Qdrant/Chroma, field-exists on pgvector, reject-all on FAISS; AND/OR/NOT are translated in `search()` only — `get_all()` forwards raw `OR/AND/NOT` keys, which match nothing on pgvector and FAISS (Qdrant's key_map accepts both spellings); FAISS post-filters after only `top_k*2` over-fetch (`faiss.py:403`) so heavily filtered queries lose recall. Unsupported operators are NOT uniformly "ignored": Qdrant/pgvector raise `ValueError`, Chroma falls back to `$eq`, and FAISS `_apply_filters` (`faiss.py:419-443`) returns `False` for every row on any operator dict (even `{'eq': v}`), `$or`, `$not`, or `'*'` — zero results, no error (verified live, §10.4). The list shorthand `[a, b]` is membership on FAISS/Qdrant/pgvector but equality on Chroma; an operator dict on an entity key dies earlier with a misleading "cannot contain whitespace" `ValueError` (`198-208`).
22. `update()` overwrites embedding + payload in place; old versions survive only as `history.old_memory` text (no id, no embedding, no metadata snapshot). History ordering compares `created_at` as TEXT; only DELETE normalizes to UTC.
23. Vector-store mutation and history write are not atomic; batch ADD history rows omit `updated_at/actor_id/role`; `add_history` stores NULL timestamps if omitted (sort first); no index on `history.memory_id`; history never pruned.
24. Entity linking: `_existing_entities_by_text` lists up to 10000 rows on EVERY add/update/delete (`589, 669, 1134`); `_remove_memory_from_entity_store` re-embeds entity text just to call `update()` (`684-699`); Python `linked_memory_ids` vs TS `linkedMemoryIds` — sharing one entity collection between SDKs breaks boosting; two thresholds (0.95 merge vs 0.5 recall) must not be mixed. `_remove_memory_from_entity_store` early-returns when `_entity_store is None` (`665`); `infer=False`/procedural memories never get rows at all; semantic-merged spellings keep only the first as `data` (no alias list) so the exact tier misses the second spelling forever (§10.1).
25. Legacy graph: free-text relationship labels as Cypher TYPES needed sanitization (#4154, CJK punctuation); `search` returned `destination` while `get_all` returned `target`; `_add_to_graph` defaulted `user_id='user'` merging unscoped data; soft-deleted edges were stored but never readable (no rollback API); tool naming drift `establish_relationships` vs `establish_relations`.

### 10.1 Entity-linking coverage gap (G1) — which ingest paths populate the entity store
**Verified.** Exactly two writers of `{collection}_entities` rows:
- `add(infer=True)` Phase 7 (`main.py:1086-1190`; async `2746-2848`) — an inline batch implementation (one `extract_entities_batch`, one `embed_batch` with per-item fallback + pad/truncate, one `_existing_entities_by_text` scan, one `entity_store.search_batch(top_k=1)`, one batch insert). It never calls the helpers.
- `_update_memory` → `if text_changed:` → `_remove_memory_from_entity_store` then `_link_entities_for_memory` (`2094-2096`; async `3791-3793`). These are the ONLY callers of `_link_entities_for_memory` (`707-728`; async `2385-2403`), whose docstring literally says "Simpler single-memory variant of Phase 7 in add()". Per entity it calls `_upsert_entity` (`605-650`): embed → exact match via `_existing_entities_by_text` (lists ≤10000 rows **per entity**, `610`) → `entity_store.search(top_k=1)` ≥ 0.95 (`621`) → append id + `update(vector=None)` (`624-635`) or insert uuid4 row (`636-649`).

Never linked: `_create_memory` (`1961-1991`; async `3634-3669`) = embed → payload → `vector_store.insert` → `db.add_history('ADD')`; no entity call although `metadata` already carries the identity keys from which `session_filters` could be derived exactly as `2093` does. Its callers: `infer=False` (`903`; async `2564`) and `_create_procedural_memory` (`2031`; async `3726`). `infer=False` also skips `db.save_messages` (Phase 8, `1193`), so raw messages never become Phase-0 context for later `infer=True` calls.

Retrieval consequence: `_compute_entity_boosts` (`1733-1813`) fans out only over `payload.linked_memory_ids` (`1805-1808`) — an atom without an entity row can never be boosted — and `score_and_rank` adds 0.5 to `max_possible` whenever ANY candidate has a boost (`scoring.py:95-101`). In a scope mixing raw and extracted memories, an entity-bearing query deflates the raw memories' relative score even when their text literally contains the queried name. The only "repair" is a later `update(text=<different>)`; `update(metadata=)`/`update(expiration_date=)` do not relink (`text_changed` gate `2056`).

Additional gotchas (beyond §9 #24):
- `_remove_memory_from_entity_store` early-returns when `self._entity_store is None` (`665-666`): a fresh process that calls `delete()` before any add/search leaves stale `linked_memory_ids`; harmless for candidates (deleted ids are never candidates) but inflates `num_linked` and damps surviving memories' boosts.
- Many-to-many stored as a list in a vector payload → every link/unlink is a read-modify-write of the whole entity row (root of #5553; async `delete_all` now passes `skip_entity_cleanup=True` (`3592`) then `_bulk_clear_entity_store` (`2319-2338`)); sync `delete_all` stays O(memories × entity rows) via `list(top_k=10000)` per memory (`669`).
- Phase 7 sorts `linked_memory_ids` (`1158/1175`), `_upsert_entity` appends (`626`): two shapes for one field.
- Semantic dedup (0.95) keeps the FIRST spelling as `data`; no alias list, so the exact tier misses the second spelling every time and falls through to the semantic tier.
- Phase 7 scopes entity rows by session identity keys only (`search_filters`, `924`); `actor_id` and per-message `role` are ignored.
- `extract_entities` is English-only (`en_core_web_sm`); `get_nlp_full` latches `_load_failed_full` (`spacy_models.py:49-64`) → `[]` for the process lifetime; Chinese text yields no entity rows — HMS Elite cannot reuse this extractor as-is.
- Phase 7 is non-transactional after Phase 6 (a crash between them = same effect as the `infer=False` gap); no backfill job exists.
- Docs (`docs/core-concepts/how-it-works.mdx:33,45-49`) say entity extraction happens for "each memory" and describe `infer=False` only as "store raw content exactly as provided"; the only linking tests assert `_link_entities_for_memory`/`_remove_memory_from_entity_store` NOT called on an expiration-only update (`tests/test_main.py:245-267`, `tests/memory/test_main.py:216-239`). The gap is untested.
- Query-time constants (`top_k=500`, similarity ≥ 0.5, `1775/1793`) and link-time constants (`top_k=1`, ≥ 0.95) are independent literals, not shared config.

Port to HMS Elite:
- ONE linker: `link_atom_entities(store, atom_id, text, scope) -> list[str]` in `ingest.py` (bilingual docstring, "State effect: writes atom_entity"), invoked inside the single `create_memory_atom()` primitive so SourceEvent→Observation, raw message atoms (`atom_type='message'`, the `infer=False` analog), EP/Case atoms, procedural/skill distillation and StateFeedback "add corrected state" (§3.10) all populate `atom_entity`. Port to HMS Elite:
- Validity is a store-level predicate, not a per-reader post-filter: one `_validity_clause(as_of, include_expired)` in `store.py` (`valid_from <= :as_of AND (valid_to IS NULL OR valid_to > :as_of)`) used by every read of `memory_atoms` — `get_atom`, `list_atoms`, AxisQuery execution in `mvmi.py`, Support Graph Refine, ContextIR compile, prune. `ix_atoms_validity(valid_from, valid_to)` (§7.4) plus a partial index `ON memory_atoms(valid_from) WHERE valid_to IS NULL` and one on `(valid_to)`. Mem0's over-fetch `max(limit*4,60)` exists only because expiry is a post-filter; with validity in WHERE, `AxisQuery.limit` pushes straight to SQL.
- `AxisQuery(as_of: str | None = now-UTC, include_expired: bool = False)` and the same two knobs on get-by-id; one `as_of` per ContextIR compile so facts/episodes/preferences are consistent — this is the `reference_date` OSS refuses, and §4.2 temporal queries are as-of queries over the validity axis.
- Canonical instants: full ISO-8601 UTC, ALWAYS fixed-width via `isoformat(timespec='microseconds')` so TEXT order == chronological order in SQLite; never rely on `DATETIME()`.
- `hms/timeutil.py`: `now_iso()`, `to_utc_iso(value)` (accepts `Z`, `±HH:MM`, naive-assumed-UTC, `datetime`/`date`, epoch int; raises on garbage), `parse_iso(value)`; applied at the SourceEvent boundary (§3.1 `SourceEvent.timestamp`) and at every store write (`Anchor.timestamp`, `MemoryAtom.time_anchor/valid_from/valid_to`, EP timestamps, `StateFeedback.created_at`). Merge Mem0's two naive policies into the single naive→UTC rule.
- Never persist a literal `None` to clear `valid_to`: `store.update_atom(atom_id, *, valid_to: str | None | Unset = UNSET)` with clear = `SET valid_to = NULL` on the relational column.
- Validate on all input channels (ingest, consolidation, feedback `state_outdated`), fail closed — never Mem0's `except ValueError: return False`.
- Expiry is a revision, not a hidden flag: `valid_to = now` on the old atom PLUS a Support Graph `revision` edge to its successor (§3.7, §3.10), so history/Refine can show WHY an atom stopped being valid.
- Ingest's "equivalent atom exists" check and consolidation merge query with `include_expired=False` (or treat a match against an expired atom as "reactivate via revision edge") — otherwise expired states become zombies that block re-learning.
- Prune / `decay_stale_state` (§3.9) is the ONLY path touching expired atoms and reports `{live, expired}` counts separately.
- Three distinct instants on Anchor/MemoryAtom — event time, ingest time (`created_at`), validity window — all in the canonical shape.
- No `pytz` (stdlib `timezone.utc`/`zoneinfo`), no per-store `timezone` setting; the store is UTC-only and conversion happens only at the Renderer (§2).
