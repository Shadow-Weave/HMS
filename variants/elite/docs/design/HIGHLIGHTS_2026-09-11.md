# HMS Elite 这一版：核心设计与洞察（2026-09-11）

一句话：把「记忆」当成可审计、可修订、可解释的状态来存，而不是一堆可检索的句子。对外是 Mem0 的皮（11 个同签名方法、同信封、同 filters），对内是 HMS 双平面。下面每一条都附本轮实测的证据和代价；没有测过的写「未测」。

## 1. 五个结构性设计决定

### 1.1 双平面：索引平面找，支持图继承

State Index 存 7 个轴（时间、有效期、实体、主题、角色、情绪、尺度），原子不存边；Support Graph 存 6 类边（temporal / causal / revision / conflict / use / distill），每条边至少一个见证锚点。`search` 只读索引平面，`why` / `compile(deep)` / 巩固才碰图。

- 证据：9 任务消融里 axis_only 均值 0.65，axis_graph 0.90，axis_graph_support 1.00；`search` 路径由测试断言不触碰任何 `graph_*` 表。
- 代价：两套结构要同步；InterfaceEP 的粗化只在后台巩固里做，写入路径不承担。

### 1.2 无见证无意义 + 修订代替删除

写入分两段事务：Txn A 先把原话与 sha256 锚点落库并提交，LLM 抽取与嵌入在锁外，Txn B 才物化原子、边、索引。删除是归档，`BEFORE DELETE / UPDATE` 触发器拒绝物理删改。

- 证据：首轮真实跑丢了 31% 窗口的抽取结果，原话一条没丢；本轮能把 r1/r2/r3 三轮 10,611 条真实 deepseek 观察零 API 回放并重建库，靠的就是锚点加记录回复。错题集每张卡能并排放出 gold 窗口原文，也是同一条链。
- 代价：库体积单调增长，实测 6.5 KB/原子（含源事件、锚点、FTS、384 维向量）。

### 1.3 有界多通道召回 + 池内打分

语义 ANN、FTS5 关键词、实体三路各取 K（top-k 20 时 80 / 40 / 40，池上限 320），近因通道只在时间门、时间路由或召回不足时启用；scope、有效期、尺度作为硬门下推到 SQL；池内按 1.0 / 0.5 / 0.5 / 0.25 / 0.25 加权，半衰期 30 天。有一条等价性定理测试：库不超过最小 K 时与穷举逐位相同。

- 证据：sqlite 上 search@30,000 从 1.6 s 降到 3.4 ms；EgoLife 离线对照纯语义 hit@20 10.8%，五信号 31.4%（mem0 同嵌入 10.3%）；真实嵌入下 r3 hit@20 78.9%，检索中位 11.4 ms、P95 28 ms、零 API 费用。
- 代价：关键词通道没有 IDF，转述动词（mention / say / ask）会劫持召回，错题集里 E104 就是这样丢的。

### 1.4 规整而不拒绝的抽取契约，compact 输出可选（当时默认 full；2026-09-18 起默认 lines，见变更记录第 108 行）

LLM 面向的每个字段都只规整、不拒绝：枚举折叠到默认、置信度按百分制或词级换算、日期回退、说话人落 `speaker` 并映射到 `actor_id`；只有见证完整性（event_idx 越界）和字段类型错误仍跳过。compact 契约（可选，`ingest.extraction_output = 'compact'`）让模型每条观察只输出 9 个键（id / event_idx / text / type / speaker / supersedes_hint_ids / when / valid_to / entities），主语、谓词、关系、情绪、主题、实体由本地推导；库默认是 full。

- 证据：改前 r2 一批就有 208 条观察因 `attributed_to` 写了人名被 pydantic 整条拒绝；改后 10,611 条回放 0 拒绝。compact 在同 18 批上输出 token 中位 2,793 对 full 5,631，撞 8,192 上限 0 对 8 次，每批模型耗时 8.7 s 对 17.1 s；204 题零 API 回放 A/B 的 hit@20 161 = 161，实体轴 8,439/8,439 对不窄于 full。
- 第三种契约 lines（2026-09-12，文本行，观察一行一条）：测量结果（2026-09-12，`results/real/elite_lines_full204`，204 题全量，deepseek-flash，空闲档）：记忆行上下文 54.9%（112/204），状态卡片上下文 63.2%（129/204，所有臂中最高）；hit@20 84.3% / 82.4%（最高）；每窗口输出 51 token（full 495、compact 157、mem0 45），每批模型耗时中位 3.76 s（full 14.9、compact 7.3、mem0 3.5），写入 + 回答全按空闲价 ¥2.24（mem0 ¥1.98、compact ¥4.35、full ¥11.56）；存入 12,994 条原子（2.68 条/窗口，库 72.5 MB）；判定 ADD 12,963 / NONE 20 / UPDATE 11；零截断、零丢失。结论：成本与写入速度达到 mem0 水平且召回更高；记忆行上下文的准确率低于 full 4 个点（有据答错 72 题），状态卡片上下文高于 full 1.4 个点。库默认仍为 full；成本敏感且读侧走状态卡片的场景推荐 lines。（2026-09-18 起默认 lines，见变更记录第 108 行；读侧 `HMS.context()` 混合上下文 70.1%，READER_AB_2026-09-18.md）
- 默认值：compact 在 2026-09-11 当天曾为默认，同日晚回退为 full。真实 204 题运行中 compact 初版记忆行 53.9%，根因是模型把观察 i 与候选 i 配对判 NONE（1,685 个 NONE，22% 陈述未入库）；判定措辞重写加 `verdict_min_similarity` 守卫后的修订版（elite_compact_v2_full204）记忆行 56.4%（115/204）/ 状态卡片 62.7%（128/204），hit@20 77.9% / 79.4%，NONE 15，窗口丢失 0，空闲价 ¥4.35，每批 7.3 s；full r3 61.3% / 61.8%，hit@20 78.9%，¥11.56，14.9 s。56.4 比 61.3 低 4.9 个点，超出事先定的 2 个点容忍（CONTRACT §6.5）。compact 仍推荐给成本敏感的批量灌入（写入费用 0.38 倍、每批耗时 0.49 倍）与状态卡片阅读器。（2026-09-18 起默认 lines，见变更记录第 108 行）
- 代价：compact 下 confidence 一律 0.7，topic_tags 由本地词典给出；抽取丢失（25 道错题）说明细节保真还要在 text 上约束。

### 1.5 状态输出层与接口对齐

`compile` 产出六槽 ContextIR 与工作状态卡；StateAPI 提供 12 个业务状态委托（work_state、handoff_package、personal_state 等）；hms4eye 的 7 方法适配器逐字对齐，点亮对方 33 个 no-op 中的 13 个；AsyncHMS 镜像 40 个方法（同步包装）。

- 证据：状态卡片上下文答题 61.8%，记忆行 61.3%，持平；但卡片每题输入 1,606 token，记忆行 332 token。
- 代价：卡片在 EgoLife 这类问答上没有换来准确率，它的价值在需要「当前有效事实 + 失效假设 + 下一步」的工作场景，这次没测。

## 3. 从数据里学到的七条

1. **瓶颈已经从「找不到」移到「找到了答不对」。** 无据 24 题，有据答错 55 题。再多存记忆帮不上后者，要改上下文的形状和阅读器。
2. **时间是一等轴，却没进上下文。** 10 道时间推算题，问「上次…」的题低 10 个点，原因只有一个：记忆行不带 time_anchor。这是最便宜的一次提升。
3. **抽取要保细节，不是保条数。** 25 道抽取丢失里，gold 批次的记忆都在，丢的是数量、计划、时间这类细节。compact 契约减了 token，text 的完整性约束要跟上。
4. **写入的钱和时间都在输出 token 上。** 输入 80% 命中缓存（¥0.02 / 百万），输出 ¥4 / 百万；「让模型少说」比「少给它看」值钱 200 倍。
5. **语言鸿沟是真实存在的丢失。** 英文入库、中文提问，「樱桃小丸子」变成 Chibi Maruko-chan 后三路都够不到。实体要双语，或把 text_zh 一起入库。
6. **稳定性来自不拒绝。** 首轮 31% 的窗口丢失全部来自校验门；LLM 面向的字段一律规整，这是规则不是修补。
7. **修订不删除的账要算清。** 每用户每月 9–15 MB，一年上百 MB；归档与分库策略要在产品化前定。

## 4. 已知短板与未做

- Milvus-lite 检索 11–49 ms（哈希嵌入），没到个位数毫秒；真实嵌入下未测。
- 重排器有接口（overlap / llm），评测里没启用。
- 多模态入口（多部件消息、视觉钩子）有代码，没有视觉数据进来，未测。
- 写入并发固定 1；评测台按顺序记账，改并发要重做归属。
- 中文 token 数按英文同量级假设；单句探针是英文。
- 与 mem0 的真实 LLM 同口径对照已完成（`EGOLIFE_REAL_LLM_MEM0_VS_ELITE_2026-09-11.md`）：mem0 56.9%、¥1.98；Elite full 61.3%、¥11.56；Elite compact 修订版 56.4% / 状态卡片 62.7%、¥4.35；Elite lines 54.9% / 状态卡片 63.2%、¥2.24。以状态卡片为读侧时 lines 用 mem0 的价钱拿到最高准确率；以记忆行为读侧时 full 仍最高、贵 5.8 倍。
- 状态卡片、StateAPI 在工作场景的价值未测。
